# 微流程节点「每种可能性」动态验证（子模式切换，2026-10-28）

> 证据等级：**LIVE** —— 每种子模式均在 test2 真实画布「添加 → 切子模式 → 读回字段」走通。
> 本文是 `node-modal-and-value-editor.md`（静态契约）的**动态验证**，不是重新定义。
> 探测脚本：`scratch/probe_variants.py`；证据：`scratch/variant-evidence/VARIANTS.json`。

## 一、覆盖范围

24 类节点里，**12 类含「子模式」**（切换后字段/必填变化），共 **40 种切换态**，全部动态验证通过。

子模式控件三类：**radio**（查询方式/错误提示方式/事件类型/映射值类型）、
**select**（删除规则/变量类型/操作类型/目标数据对象类型）、**tabs**（赋值方式）。

## 二、三条关键发现

### 2.1 子模式控件类型 ≠ 静态契约假设

`node_modals` 里 `control` 字段常留空或写错。实测真实控件：

| 节点 | 子模式字段 | 真实控件 |
|---|---|---|
| 查询单条/多条 | 查询方式 | radio（非 toggle） |
| 删除数据 | 删除规则 | select |
| 创建变量 | 变量类型 | select |
| 插入数据 | 赋值方式 | tabs（字段映射/对象引用） |
| 列表操作/映射操作/修改列表 | 操作类型 | select |

### 2.2 真实下拉选项 ≠ node_modals 分组标题

`node_modals/LIST_OPERATION.json` 的 `operation_types` 是分组标题
（聚合/筛选/集合/取值/分组/其他），但真实下拉选项是**子项**：

```
计数 / 过滤 / 去重 / 第一条 / 最后一条 / 第N条
```

映射操作的真实选项：`获取 / 赋值 / 删除 / 获取键列表`。

**结论：静态契约里的分组标题是「语义分类」，不是可点选项。生成器/探测器必须用真实下拉选项。**

### 2.3 赋值方式是级联字段（选前置后才出现）

更新数据（CHANGE_ENTITY）和自定义服务（CUSTOM_SERVICE）的「赋值方式」字段，
**在未选「选择更新的数据」/「选择服务」前不渲染**（抽屉里根本没有这个 form-item）。

这印证了 `node-authoring-contract.md` §十「每个节点选择都触发接口加载数据」——
子模式字段是级联的，不是静态固定的一套。

### 2.4 查询多条「分页查询」默认值坑（pageSearch）

查询多条数据（RETRIEVE_ARRAY）条件查询模式下，`pageSearch` 前端回填默认是字符串 **`"true"`**
（分页查询=是），导致 `pageInfo`（分页数据）变必填 → 保存被 firstErrorNode 报 `pageInfo null` 阻塞。

权威默认值在 `node_templates/RETRIEVE_ARRAY.json`：**`pageSearch: "false"`，`pageInfo: null`**（分页查询=否，
pageInfo 允许空）。修复 = 把「分页查询」radio 切到「否」。注意 pageSearch 是**字符串** `"true"`/`"false"`，不是布尔。

★ radio 切换坑：ant-radio 的 input 是隐藏的（opacity:0），CDP 点 input/wrapper 的 getBoundingClientRect
中心都不触发切换（实测点「否」后 radio 仍「是」checked）。需点 `.ant-radio` 视觉圆点或走 React onChange，
待坐实。

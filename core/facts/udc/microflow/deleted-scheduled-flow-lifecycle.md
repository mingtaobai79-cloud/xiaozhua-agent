# DELETED_SCHEDULED_FLOW_MAY_EXECUTE_AGAIN

**一句话**：删掉一条定时微流程后，**调度器仍可能按缓存再触发若干轮**，直到重新构建应用才真正停止。

## 证据分级

| 级别 | 内容 |
|---|---|
| **VERIFIED**（真实运行，两次独立复现） | 第一次：流程 `p5df616979` 19:09 删除，19:12 仍执行一轮（数据流日志 6→9 条）。第二次：`p5subp619804` 20:07 前后删除，20:11、20:16 又各跑一轮（迁移断点表各 +2 行）。两次都在**重建应用**后停止：重建完成后的下一个周期不再产生数据（19:22 / 20:21+ 均 0 行）。 |
| **未验证** | 缓存失效的确切时长与判定条件（是否与构建产物版本绑定）未深挖；只确认「重建后停」。 |

## 正确清理顺序

```
1. 删除临时流程
2. 清理测试数据
3. 触发一次 RELEASE 构建（让包里不再含该流程）
4. 等满一个调度周期（定时流程通常 1~5 分钟）
5. 复查：① 流程列表无残留 ② 定时任务已停 ③ 测试数据不再新增
```

**只做第 1、2 步就宣布清理完成是错的**——数据还会继续长出来。

## 给测试的硬性要求

- 计划任务型测试流程必须记录「删除时刻」与「最后一条数据时刻」，用来证明停止。
- 清理检查必须包含**数据不再增长**这一项，而不只是「流程查不到」。

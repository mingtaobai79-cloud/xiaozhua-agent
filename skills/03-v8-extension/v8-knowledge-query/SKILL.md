# V8 知识查询

凡是 V8 开发、客开、产品框架、SPI/API、组织/BPM/集成或公司内部资料问题，默认优先使用工作台资料，不把它当作普通常识问答。

## 工具怎么选

不要把源码检索合成一个接口。按问题类型选工具：

1. 查文档、客开怎么做：`get_development_context` / `search_v8_knowledge`
2. 口语找公开接口，例如「同步部门有哪些增删改接口」：`resolve_v8_api`（向量命中后自动 Zoekt 定位）。只要签名时才用 `search_v8_public_apis`
3. 已知类名、方法名、要文件位置：`search_v8_code` / `find_v8_symbol`（Zoekt 全仓文本）
4. 已知类名要读类体：`get_v8_type_source`
5. 核对调用和测试：`get_v8_usage_examples` / `get_v8_code_context`
6. 按路径读片段：`read_v8_code`，带行号范围，不要整仓灌进对话

`search_v8_public_apis` 只覆盖 facade/api/services 的公开签名，不能替代 Zoekt，也不是知识库。


## 固定检索顺序

1. 首先调用 `get_platform_context`，确认资料数量、版本边界和代码目录；该调用由工作台自动统计员工身份。
2. 工作台检索已混合全文和向量，调用方不要换工具。默认只传 `query`：先调用 `get_development_context(query)`，必要时再调用 `search_v8_knowledge(query)`。不要传 `module`。
3. 禁止把「架构/开发方式、业务领域、后端开发、前端开发、V8、UDC、Java、React」等主题词放进 `module`。这些词必须写进 `query`。
4. 中文整句不要只查原句；拆出业务短语和英文术语再查一次。例如“后端客开有哪些方式”继续查“后端客开、UDC、Facade、Dubbo、SPI、CIP”。向量会补近义，但类名/接口名仍要用精确词检索。
5. 只有用户明确给出资料库里已经存在的模块名时，才可以传 `module`；不确定就省略。
6. 若问题需要源码事实：口语找公开接口用 `search_v8_public_apis`；已知类名/方法名再用 `find_v8_symbol`/`search_v8_code`，按“定义 → 调用 → 测试”核验。

## 命中后的回答契约

- **命中资料时必须提供知识引用**：回答末尾固定增加“知识引用”小节；每条关键结论就近标注 `[citation_id]`，并列出引用 ID、资料路径、标题、版本/模块和相关片段。
- 引用只使用 MCP 返回的 `citation_id` 和字段，不自行编造链接、接口或版本；多条资料冲突时并列展示并标记待确认。
- 资料命中只证明文档有依据，不代表已核对当前代码；涉及实现细节时同时标注“源码已核实”或“源码未核实”。
- 命中资料后不得只给通用经验；通用建议必须单独标记为“通用工程建议”，不能冒充 V8 事实。

## 未命中与安全边界

- 没有命中时明确写“知识不足：当前资料未覆盖”，给出待验证项和下一组检索词，不要编造结论。
- 只读 Markdown 与员工确认后的知识沉淀由同一索引和引用格式提供；默认不把完整对话、原始日志、Token、密码、连接串或完整本地 Diff 上传到工作台。
- 未登记代码目录或工具拒绝源码访问时，只能使用 Markdown 引用，不声称已经读取源码。

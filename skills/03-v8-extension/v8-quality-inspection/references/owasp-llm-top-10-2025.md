# OWASP LLM Top 10 (2025) 参考文档

> 来源：https://genai.owasp.org/llm-top-10/
> 发布日期：2025年3月12日

## 概述

OWASP Top 10 for LLM Applications 2025 是面向大语言模型（LLM）和生成式 AI 应用的安全风险清单。涉 AI 功能的系统在安全审计时必须对照本清单检查。

## 十大 LLM 安全风险

### LLM01:2025 - Prompt Injection（提示注入）
- **描述**：用户提示可改变 LLM 的行为，使其偏离预期任务。包括直接注入（用户直接输入恶意提示）和间接注入（攻击者将恶意指令嵌入 LLM 可访问的外部内容中）。
- **审计要点**：
  - 系统提示与用户输入是否分离
  - 是否对用户输入做了约束/过滤
  - LLM 可访问的外部内容是否可被注入
  - 输出是否经过校验后才用于后续操作

### LLM02:2025 - Sensitive Information Disclosure（敏感信息泄露）
- **描述**：敏感信息可能影响 LLM 及其应用。包括训练数据泄露、上下文中的敏感信息回显、系统提示泄露。
- **审计要点**：
  - 训练数据是否包含敏感信息
  - LLM 上下文/记忆中是否存储了敏感数据
  - 输出是否可能泄露系统提示或内部配置

### LLM03:2025 - Supply Chain（供应链）
- **描述**：LLM 供应链易受多种漏洞影响，包括模型来源、训练数据来源、第三方插件、向量库等。
- **审计要点**：
  - 模型来源是否可信
  - 第三方插件/工具权限
  - 向量库/嵌入数据的完整性
  - 训练数据供应链安全

### LLM04:2025 - Data and Model Poisoning（数据与模型投毒）
- **描述**：预训练、微调或嵌入数据被篡改可导致模型行为异常。
- **审计要点**：
  - 训练/微调数据来源校验
  - 数据投毒检测机制
  - 模型完整性验证

### LLM05:2025 - Improper Output Handling（不安全的输出处理）
- **描述**：LLM 输出未经充分验证、净化和 sanitization 就被传递给下游系统（如 eval、SQL、HTML 渲染）。
- **审计要点**：
  - LLM 输出是否经过校验/净化后才用于后续操作
  - LLM 输出是否直接进入代码执行（eval/exec）、SQL 查询、HTML 渲染
  - 是否将 LLM 输出等同于不可信用户输入

### LLM06:2025 - Excessive Agency（过度代理）
- **描述**：LLM 系统被授予过大权限，可执行破坏性操作或访问敏感数据。
- **审计要点**：
  - AI 可调用的工具/函数权限是否最小化
  - 是否有 human-in-the-loop 审核关键操作
  - 工具执行的权限范围是否限制
  - 是否有速率限制和资源约束

### LLM07:2025 - System Prompt Leakage（系统提示泄露）
- **描述**：LLM 的系统提示可能通过特定技巧被泄露，暴露内部逻辑、规则和配置。
- **审计要点**：
  - 系统提示中是否包含敏感信息
  - 是否有防泄露机制
  - 敏感配置是否放在系统提示中

### LLM08:2025 - Vector and Embedding Weaknesses（向量与嵌入弱点）
- **描述**：向量和嵌入系统存在安全风险，包括未经授权访问、数据投毒、跨租户泄露。
- **审计要点**：
  - 向量数据库访问控制
  - 嵌入数据来源验证
  - 多租户隔离

### LLM09:2025 - Misinformation（错误信息）
- **描述**：LLM 产生的错误信息（幻觉）对依赖 LLM 输出的应用构成核心风险。
- **审计要点**：
  - 关键决策是否有人工复核
  - 是否有事实校验机制
  - 输出是否标注不确定性

### LLM10:2025 - Unbounded Consumption（无限制消耗）
- **描述**：攻击者可利用 LLM 的高资源消耗特性进行 DoS 攻击。
- **审计要点**：
  - 速率限制（每用户/每 IP）
  - 令牌/配额管理
  - 最大输入长度限制
  - 资源监控与告警
  - 模型推理成本控制

# OWASP Top 10:2025 参考文档

> 来源：https://owasp.org/Top10/2025/ （2025年11月发布，2026年1月定稿）
> 引用时标注：OWASP Top 10:2025 A01~A10

## 概述

OWASP Top 10:2025 是第八版，基于真实漏洞数据和社区调查。相比 2021 版，新增两个类别（A03 软件供应链失效、A10 异常条件处理不当），SSRF 并入 A01，安全配置错误从 #5 升至 #2。共映射 248 个 CWE（2021 版为 218 个）。

## 十大类别

### A01:2025 - 失效的访问控制（Broken Access Control）
- **排名变化**：保持第 1 位（连续四版居首）
- **覆盖率**：约 3.73% 的受测应用存在此类弱点，映射 40 个 CWE
- **2025 变化**：SSRF（服务端请求伪造）从 2021 版的独立 A10 并入此类
- **审计重点**：
  - 水平越权（IDOR/CWE-639）：改 ID 访问他人数据
  - 垂直越权（CWE-862/863/284）：普通用户访问管理功能
  - 对象级授权（BOLA）：API 中每个数据访问都需校验
  - SSRF（CWE-918）：用户可控 URL 的服务端请求，需校验目标（禁内网/元数据地址 169.254.169.254、DNS 重绑定防护）
  - 路径遍历（CWE-22）：`../` 与 URL 编码绕过
- **修复要点**：默认拒绝（deny by default）、服务端独立校验、对象级授权检查

### A02:2025 - 安全配置错误（Security Misconfiguration）
- **排名变化**：#5 → #2
- **覆盖率**：约 3.00%，映射 16 个 CWE
- **审计重点**：
  - 默认凭证、示例应用、不必要的功能
  - 调试模式、Swagger UI、Actuator 端点暴露
  - CORS 配置过宽（`*` + `credentials: true`）
  - 安全响应头缺失（HSTS、CSP、X-Frame-Options、X-Content-Type-Options、Permissions-Policy）
  - 云存储权限过宽（OSS/S3 public read）
  - IaC 错误配置（Terraform/K8s YAML 中的权限放通）
  - 错误页面泄露堆栈信息

### A03:2025 - 软件供应链失效（Software Supply Chain Failures）【新增】
- **替代**：2021 版 A06"易受攻击和过时的组件"，范围扩大
- **特点**：数据中发生次数最少，但 CVE 平均可利用性和影响分数最高
- **审计重点**：
  - 依赖 CVE 检查（对照 NVD/OSV）
  - 锁文件使用（package-lock.json/yarn.lock/go.sum）
  - 依赖扫描工具（npm audit/pip-audit/govulncheck/Snyk/Trivy）
  - SBOM 生成（CycloneDX/SPDX）
  - 制品签名与来源验证（SLSA 等级、Sigstore/cosign）
  - CI/CD 管道完整性（分支保护、最小权限令牌、构建可重现）
  - 私有源/代理源可信性

### A04:2025 - 加密失败（Cryptographic Failures）
- **排名变化**：#2 → #4
- **覆盖率**：约 3.80%，映射 32 个 CWE
- **审计重点**：
  - 弱算法：MD5/SHA1/DES/RC4 仅限非安全场景
  - 密码哈希：bcrypt(≥12轮)/scrypt/argon2id + 盐
  - 传输安全：TLS 1.2+，禁用旧版本
  - 敏感数据落库加密：AES-256-GCM
  - 密钥来源：KMS/环境变量/Vault，禁止硬编码
  - 随机数安全：SecureRandom/secrets，禁 random/Math.random 做安全用途
  - 密钥轮换机制

### A05:2025 - 注入（Injection）
- **排名变化**：#3 → #5（含 XSS）
- **审计重点**：
  - SQL 注入（CWE-89）：参数化查询/ORM；注意 ORDER BY/表名/列名无法参数化的位置
  - 命令注入（CWE-78/77）：参数数组执行
  - XSS（CWE-79）：按上下文编码（HTML/JS/URL/CSS）
  - LDAP 注入、NoSQL 注入（$where/操作符注入）
  - 模板注入（SSTI）、表达式注入（SpEL/OGNL）
  - 日志注入（CRLF）、XXE（禁用外部实体）

### A06:2025 - 不安全设计（Insecure Design）
- **排名变化**：#4 → #6
- **审计重点**：
  - 缺失威胁建模
  - 业务逻辑设计缺陷（支付篡改、优惠券重复使用、竞态条件）
  - 信任边界处缺少服务端校验
  - 关键业务缺少防重放、防篡改（签名）、频控/风控

### A07:2025 - 认证失败（Authentication Failures）
- **更名**：从"身份识别和身份验证错误"改为"认证失败"
- **审计重点**：
  - 密码策略与存储（最小长度 8 字符，建议 15+）
  - 登录防爆破（限流、验证码、锁定）
  - 多因素认证（高敏感场景）
  - 会话管理：令牌随机性（≥128bit 熵）、过期、HttpOnly/Secure/SameSite
  - JWT：算法固定（禁 alg:none/算法混淆）、短时效、声明校验、撤销机制
  - OAuth/OIDC：state 防 CSRF、redirect_uri 白名单、PKCE

### A08:2025 - 软件或数据完整性失败
- **审计重点**：
  - 不安全反序列化（CWE-502）：Java 原生序列化、Fastjson autoType、Python pickle、PHP unserialize
  - 自动更新/插件下载未校验签名
  - CI/CD 产物可追溯性

### A09:2025 - 安全日志与告警失败（Security Logging and Alerting Failures）
- **更名**：从"安全日志和监控故障"改为"安全日志记录和告警失效"，强调**告警**
- **审计重点**：
  - 认证成功/失败、授权失败、管理操作、关键业务操作是否记录
  - 日志元数据：时间(UTC)、用户、来源 IP、traceId
  - 日志防篡改（集中采集/只追加）
  - **告警阈值与触发机制**（只记不报等于没有）
  - 日志中敏感数据脱敏（CWE-532）

### A10:2025 - 异常条件处理不当（Mishandling of Exceptional Conditions）【新增】
- **审计重点**：
  - fail-open 逻辑：异常分支放行请求（如权限校验抛异常后返回 true）
  - 吞异常（空 catch / 仅打印继续执行）
  - 错误信息泄露内部细节（堆栈、SQL、文件路径）
  - 超时/依赖不可用时的降级路径安全性
  - 可恢复性

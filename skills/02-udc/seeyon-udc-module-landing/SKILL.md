# Seeyon UDC · 模块成果落位规范

## Purpose

当一个 UDC 域的子模块（枚举、自定义对象、选项集、页面设置…）做完一轮推进后，
把成果按**统一模式**写回 `seeyon-agent` 仓库，保证：

- 目录可读：看一眼就知道东西在哪
- 边界不越：事实 / 契约 / 脚本 / skill 四类资产各归各位，不互相污染
- 状态可辨：**真实可用**、**真实不可用**、**待删除** 三类必须分开标注
- 客户中立：仓库不含任何真实客户、人员、角色标识

本 skill 是**模式规范**，不是某个模块的操作手册。具体模块的操作细节看该模块自己的
事实格与 skill。

---

## 一、UDC 九域与子模块

| 域 | 设计器入口 | 子模块示例 |
|---|---|---|
| 应用 | 应用设计 → 应用 | custom-app、app-draft、app-online |
| 实体 | 应用设计 → 实体 | 属性、枚举字段、索引、DTO |
| 菜单 | 应用设计 → 菜单 | 菜单项、页面绑定 |
| 规则 | 应用设计 → 规则 | 生单规则、扣减规则 |
| 流程 | 应用设计 → 流程 | 微流程、审批流 |
| BI | 应用设计 → BI | 指标、图表（5.3.517 域内 0 契约） |
| 栏目 | 应用设计 → 栏目 | 栏目项（真对象是 `udc_portlet`） |
| **设置** | 应用设计 → 设置 | **枚举**、选项集、自定义对象 |
| 角色 | 应用设计 → 角色 | 角色、授权（仓库内 0 契约） |

**枚举属于「设置」域**，不是独立域。推进顺序按域走：设置（枚举 → 自定义对象）→ 应用 →
实体 → 规则 → 菜单 → …

## 二、四类资产分开落位（核心规范）

模块名记作 `<域>`，子模块记作 `<子模块>`。以 枚举 = 设置/enum 为例：

| 类别 | 路径模板 | 放什么 | 不放什么 |
|---|---|---|---|
| **实现**（可执行约束） | `components/udc/<域>/<子模块>_*.py` | 构造器、校验器、模型、分析器 | 事实叙述、报告 |
| **事实**（九段式事实格） | `core/facts/udc/<域>/<子模块>/create.md` | Capability/Version/Input/Required/Execution/Side Effects/Constraints/Evidence/Verified | 代码实现 |
| **事实**（写链细节） | `core/facts/udc/<域>/<子模块>/<子模块>-write-chain.md` | 请求体全文、错误字典、踩坑、作废声明 | 结论性叙述 |
| **操作契约** | `docs/operation-contracts/udc/<域>/<子模块>-contracts.md` | operation 清单、必填槽位、错误码对照 | 证据原文 |
| **操作脚本** | `tools/core/<域>/<子模块>_*.py` | 实际跑的操作脚本 | 库代码 |
| **skill**（宿主侧） | `skills/seeyon-udc-<域>-<子模块>/SKILL.md` | 使用说明、坑、正确姿势 | 实现代码 |
| **一次性脚本** | `tools/one-off/` | 用完的探针 | 需长期维护的东西 |

### 硬规则

1. **一个子模块只有一个事实目录**。不允许同时存在 `core/facts/udc/enum/` 和
   `core/facts/udc/setting/enum/`——两处事实必然互相矛盾。
2. **实现只放 `components/udc/<域>/`**。不要把某域的模型放在 `components/udc/` 根上，
   也不要放到别的域的目录里（越界）。
3. **事实格必须被 `core/facts/INDEX.md` 登记**，否则检索不到 = 没写。
4. **skill 不得内联实现代码**，提到构造器时必须指向 `components/udc/<域>/` 下的位置。
5. **脚本 / 事实 / 契约 / skill 不得互相复制内容**。skill 指向事实，事实指向契约，
   契约指向实现——单向引用，不重复。

### 落位后要跑的检查

```bash
# 结构闸门（每个域的落位都要有对应测试）
pytest tests/udc/test_<域>_<子模块>_asset_layout.py -q
```

这类测试锁住：实现在本域包内、事实在本域目录、旧位置不残留、skill 分别指向三类资产、
INDEX 已登记。**新模块的落位测试必须一并写**，否则下次又被摊平。

## 三、三类状态必须分开标注

每个模块的 `create.md` 的 **R-E9 Verified** 段，逐项标注等级：

| 等级 | 含义 | 判据 |
|---|---|---|
| `LIVE PASS` | 真实跑通并回读核实 | 有请求原文 + 响应 + DB/平台回读 |
| `LIVE` | 真实跑通但回读维度有限 | 有请求原文 + 响应，无独立回读 |
| `VERIFIED_STATIC_BYTECODE` | 静态证据坐实 | 反编译/字节码，未跑 |
| `UNVERIFIED` | **真实不可用/未验证** | 没做、或方法有缺口（写明缺口是什么） |
| `VACUUM` | **真实不存在** | 完备的负证据（不是"没做"） |

### 「待删除」必须单独标注

被清理掉、但会复发的对象，必须记在**独立小节**里，不混在可用清单：

```markdown
## 待删除清单（清理时处理）

| 对象 | 判定依据 | 处置 | 状态 |
|---|---|---|---|
| xxx | 引用分析无活引用 + 用户确认 | 逻辑删除（is_delete=1） | DONE 2026-10-20 |
| yyy | 同上 | 待删（需授权） | PENDING |
```

**「待删除」不是「已完成」**。写 `DONE` 必须有回读证据（删除后 DB/界面确认）。

### 禁止的写法

```
❌ "枚举域已打通"            ← 混了 LIVE 与 UNVERIFIED
❌ "页面引用分析已完成"        ← 实际是载体查错表，结论作废
❌ "已删除 363 个枚举"         ← 未说明是逻辑删除、是否先做引用分析
✅ "枚举新建/枚举项新建 = LIVE PASS；分组删除 = VACUUM（平台无该端点）；
    规则引用分析 = UNVERIFIED（扣减/生单规则未纳入载体清单）"
```

## 四、客户 / 人员 / 角色信息必须清除

seeyon-agent 是**可复用资产**，不能带任何真实客户标识。

### 必须清除的

| 类别 | 例子 | 替代写法 |
|---|---|---|
| 人员姓名 | 真实姓名 | 角色代号（`operator-a`）或省略 |
| 工号/账号 | `test-account-N` | `test-account-1` |
| 客户应用名 | `datamigration<数字>` | `<app>` / `datamigration_test` |
| 客户实例标识 | `znxmglpt<数字>` | `<instance>` |
| 客户组织名 | 具体公司名 | `客户A` / `本客户` |
| 角色/权限标识 | 具体角色名+授权组合 | `role-x` |
| 凭据 | token / cookie / 密码 | 一律不落盘（只写"从环境变量读"） |
| 联系方式 | 手机 / 邮箱 | 一律不出现 |

### 允许保留的

```
✓ 平台自身的对象名与类名（UdcEnumController、ctp_enum…）——这是平台事实，不是客户信息
✓ 平台 URL 主机名（lowcode-test2.*）——这是环境标识，不是客户身份
✓ 内部编号（traceId、appId 的数值）——仅当它不指向具体客户应用
✓ 作者代号（ 小爪 🐾 ）
```

### 边界规则

**原始证据文件**（平台接口返回的机器数据：抓包 JSON、DB 导出、反编译产物）
可以保留客户标识——它们是**可复核证据**，删了就无法复核。
但**结论性文档**（事实格、契约、skill、README、STATUS）必须脱敏。

**个人沟通记录**（邮件、工单、聊天导出）是例外：**必须脱敏**。
它们含人的姓名、邮箱、沟通内容，复用风险最高；脱敏后保留结构与行数，
以便证明"当时抓到了什么"。

**配置类文件**（`config/*.yaml`、Nacos 配置导出）属于活跃配置，
含客户实例名与网关域名，**必须脱敏**，但要保留配置结构（键名、层级、引用关系）
——那是配置契约的一部分。

### 三类区间的处理矩阵

| 区间 | 判据 | 处理 |
|---|---|---|
| 原始数据证据 | 平台接口返回 / 反编译产物 / DB 导出 | **保留原文**（可复核性前提） |
| 个人沟通记录 | 邮件 / 工单 / 聊天导出 | **必须脱敏** |
| 活跃配置 | `config/*.yaml`、Nacos 配置 | **必须脱敏**，保留结构 |
| 结论性文档 | `.md` 契约 / 事实格 / skill / README | **必须脱敏** |
| 代码 | `.py` | **必须脱敏**（注释里的示例值也算） |

⚠ 第一版按「目录路径」判证据边界，误改了原始抓包 json——
纠正后的判据是**内容性质**（机器数据 vs 人的记录），不是路径。

### 脱敏前先普查「契约位」

**有消费关系的值不能随手替换。** 替换前逐个问：这个值被谁读？

```
app 名 → 提取数字尾号当 appId        → 代号必须带数字尾号
生成类名 vs 黄金样本类名比对          → 代号要让两侧派生结果一致
manifest 里的 path → 指向具体文件      → 改名要同步改引用
sha256 → 与文件内容绑定              → 只改标识，不改校验和
文档正文里的示例值                    → 可自由替换
```

⚠ 代号**不能**用非数字词顶替需要数字尾号的位置——那会让消费方抛错，
表现为「构造测试一片红」，很难看出是脱敏造成的。
需要数字尾号就用保留段纯数字（`9000000000000000001`）。

⚠ 批量编辑后若全量测试红掉一片，**先回退**再重新界定范围，
不要逐个改测试期望值——那是在给破坏行为找借口。
先查是不是 CRLF/LF 差异（`git diff --numstat` 两侧行数接近即高度疑似）。

完整执行流程见 `references/deidentification-procedure.md`
（契约位普查表、代号形态选择、分区规则、基线对比、闸门自指处理）。

### 脱敏闸门

仓库有 `tests/test_deidentification.py` 强制：
- 结论区不得含工号 / 人名 / 客户应用名 / 客户实例名 / 客户组织
- 个人沟通记录不得含真实邮箱域
- 原始数据证据区**必须**保留客户标识（防止有人"彻底洗掉"导致引用全失效）

⚠ 检测规则必须**排除保留段代号**，否则闸门会持续误报，逼人去改代号——
那正是在破坏契约：
`re.compile(r"\bdatamigration(?!9000000000000000001)\d{6,}\b")`

新增模块或改动文档后，这个测试必须仍然通过。

## 五、模块收尾清单

一个子模块推进完一轮，逐项核对：

```
□ 实现归位 components/udc/<域>/<子模块>_*.py，import 路径已改
□ 事实格 core/facts/udc/<域>/<子模块>/create.md（R-E1..R-E9 齐全）
□ 写链事实 <子模块>-write-chain.md（请求体 + 错误字典 + 踩坑 + 作废声明）
□ 操作契约 docs/operation-contracts/udc/<域>/<子模块>-contracts.md
□ registry 登记该域 operation 契约（否则不可调用）
□ skill skills/seeyon-udc-<域>-<子模块>/SKILL.md
□ core/facts/INDEX.md 登记行
□ 落位测试 tests/udc/test_<域>_<子模块>_asset_layout.py
□ R-E9 三类状态分开标注（LIVE / UNVERIFIED / VACUUM）
□ 待删除清单独立小节，状态标 DONE（有回读证据）或 PENDING
□ 结论区脱敏（客户名/人员/工号/凭据/联系方式）
□ 全量测试通过，新增测试计数已同步到 README 与审计文档
```

## 六、常见坑

| 坑 | 后果 | 规避 |
|---|---|---|
| 目录搬动后 `Path(__file__).parents[N]` 失效 | 脚本读错根目录，测试静默跳过 | 搬完跑全量测试；有 API 计数断言的优先看 |
| 批量字符串替换误伤 | 把 `tools/audit/x` 里的 `audit/x` 也换掉 | 替换后立刻 `git diff` 看规模 |
| `write_text` 在 Windows 把 CRLF 变 LF | diff 几百行全变，掩盖真实改动 | 用字节写 + 显式行尾；diff 规模异常时先查行尾 |
| 脱敏时改了有契约地位的值 | 派生/比对/路径引用断裂，测试一片红 | 替换前先普查「谁消费这个值」 |
| 用非数字代号顶替需要数字尾号的位置 | 消费方抛 ValueError，症状像功能坏 | 需要数字就用保留段纯数字 |
| 批量编辑后逐个改测试期望值 | 给破坏行为找借口，掩盖真实回归 | 先回退到干净提交，重新界定范围 |
| 引用分析载体查错表 | 得出「无引用」的假结论 → 误删 | 阳性对照必须 100% 命中才敢下结论 |
| 逻辑删除当物理删除 | 回读统计误判「没删掉」 | 统计一律 `is_delete=0` 过滤 |
| 平台接口偶发报错但数据已生效 | 盲目重发造成重复操作 | 报错后先回读再决定 |
| 自动化填中文触发输入法拼音中间态 | 落库值变成拼音，平台不报错 | 编码框只填英文/数字；落库后回读核对 |
| 手写抓包不如现成工具 | 猜十几次接口名，浪费用户时间 | 先查可用抓包工具与已有 skill，再手写 |
